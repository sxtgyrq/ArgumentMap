# Argument Map 桌面操作界面

Cross 仅在全局整数坐标创建（架构 38）。半整数相交保留线路交叉，但不创建 Cross、不换路，不取整到邻近位置；线路节点仍为整数，LN 中心及线路上的逻辑位置仍保留半整数。K、导入、移动、粘贴、撤销和连接使用同一规则。显示、U/Tab 点选与各种预览仅接受合法整数 Cross；旧 Server 返回非法 Cross 时提示升级并刷新，不用旧数据继续设置通行。旧整组剪贴板含半整数 Cross 时拒绝并提示重新框选；不静默删掉关系、取整或放宽源数据版本检查。

LN8 新增 `¬ · 非（NOT）`，位于 `↔ · 等价` 之后。按输入 LN6 P → LN8 ¬ → 输出 LN6 Q 绘制，表达 `Q ↔ ¬P`，P 是唯一输入、Q 是结果。LN8 的值保存为 `¬`，只读逻辑语言自动生成为 `¬(?)`，`?` 表示尚未指定的输入命题；不接受 `¬(P)` 等具体操作数；新增、编辑、导入及复制粘贴可重复使用。统一使用 `¬`，不接受 `!`、`NOT` 或中文“非”作为值。当前架构 38，需同时更新 Server 与 WPF；NOT 仅为绘图算子，不自动绑定或改写 LN6，不计算真假或传播布尔信号，几何和 Cross 通行规则不变。

LN10 逻辑语言现在使用 `∧`（且）连接实例及各属性的隶属命题，例如 `张三∈HUMAN∧1∈HUMAN.ID∧张三∈HUMAN.NAME`。值中的参数逗号、别名和属性内容保留，逻辑语言仍自动生成且只读；新增、编辑、父类改名、导入、复制粘贴和撤销统一采用新表达式。架构 35 升级根据值重建旧 LN10 及撤销快照，不全局替换用户文本中的集合符号。

## LN 自动连接

前往/寻找的 Cross 端外延如果与其他线路形成新交点，仍经过 K 计算并设置为不连通 O；只有用户选定连接所对应的接入/接出道路与精确坐标设为普通连通 I。外延段不能把新线接通到其他线路。

“寻找”与“前往”方向相反：从穿过 LN1 的已有线路顺着可通行方向寻找接出位置，再新建 Cross → LN2 的线路。新线只穿过 LN2，不能穿过 LN1 或其他 LN；LN2 外侧延伸 5.5，Cross 端通常止于整数交点，旧节点占位时最多延伸 1 地图单位；半整数相交不作为候选，也不取整。以新增线路总长度最短选择 Cross，已有通路长度不计入成本。支持双向线路、分支和循环，遵守所有旧 Cross 的通行方向，遇到其他 LN（含擦角）即停止；不能接到旧的两线 Cross 上形成三线共交。预览青色虚线显示 LN1 → 接出 Cross，绿色新线显示 Cross → LN2，箭头方向与实际通行一致。确认时按最新地图重新检查 LN1 到接出点的可达性，不信任客户端预览点。沿用真实保存 → K → 设置 Cross 的原子流程：唯一接出 Cross 普通连通 I，其余新线 Cross 不连通 O；保留无关旧线、Cross、IsChanged 和多人编辑，失败回滚，Ctrl+Z 撤销整次新增。达到搜索上限时不能把未确认最短的候选当作成功，不退回直连。

LN 面板“连接…”与 LN 菜单“连接两个 LN…”进入两次选点；只按点击的正方形范围确定 LN，不使用文字外溢标签或保护区。必须是两个不同、已保存的 LN，适用于所有 LN 尺寸。第一次为起点、第二次为终点，完整通路按 LN1 → LN2 行进；新线默认单向，属性沿用新增默认值（速度 100）。点击不在 LN 中或重复同一 LN 时保留第一个点并给出提示。选满后弹出“直连 · 自动规划线路”“前往 · 接入已有通路”“寻找 · 从已有通路接出”“其他 · 暂未开放”，只有最后一项禁用。

直连可以是折线，系统自行选择方形内部的整数横线或竖线穿越，不要求经过点击坐标；避开其他 LN 的闭合正方形。端点和拐点都在 LN 外，非直线折角只能 90°或135°，不允许45°锐角、折返、重叠、重复节点、非法斜交或第三线穿过已有两线交点。相交仍须正交。外侧尾端至少延伸 5：因 LN 边界是半整数、线路点必须整数，实际为 5.5。地图边界内放不下尾端或未找到可行路径时给出原因，不能强行保存。

预览显示两个 LN 的 1/2 标记及线路方向，不写数据库。Enter、F6 或“确认连接”保存；Backspace 保留第一个 LN、重新选择第二个；Esc 取消。已有绘制、移动、粘贴、导入或属性窗口必须先完成，不能覆盖草稿。规划/保存忙碌期间防止重复请求和丢失预览，失败保留预览供重试或重新规划。成功更新三类地图缓存并高亮新线，Ctrl+Z 一次撤销整次新增。

规划在已认证的地图快照上运行，不持有数据库事务；直连使用有界八方向可见网格搜索，优先较短路线与较少转弯，不保证全局最短。当前直连搜索最多 12 秒、每轴 128 个候选坐标、128 个简化路径点及 4096 个细分点；未搜索到不等于地图绝对不存在路线。确认时按最新地图重新校验 LN 几何和所有线路规则。服务器在一次原子新增内依次走真实 F6 保存、同一 K 逐段计算/恢复/清理、Cross 设置流程；仅处理新线，保留其他用户的 PendingSegments/DirtyLines/StaleCrosses 和原 Cross 状态。已有 K/J 仍可后台运行、其他用户仍可操作；提交在事务中持有地图锁，异常整个新增回滚。LN 的值、逻辑语言、类型和归属不因连接而改变。

前往只穿过 LN1，不经过 LN2；目标为新增折线的总长度最短，旧线路剩余长度不计入成本，也不给转弯额外加权。从当前几何中穿过 LN2 的线路反向遍历：单向只追溯上游，双向追溯两侧；仅按已有有效 Cross 的允许换路方向分支，未设置、不连通、缺失或移走的 Cross 不换路。按道路顺序区分同一物理位置，处理多路分支、循环、多次穿过目标及线段节点，遇到任何其他 LN 的闭合范围（含擦角）即停止。无需先按 J 更新投影。

新线接入旧线的内部位置，禁止使用已有两线 Cross、非法斜交、重叠或经过其他 LN。新线后侧仍延伸 5.5，末端通常就在新 Cross；只在整数 Cross 接入；旧节点占用末端时，可沿末段最多延伸 1 地图单位，整个延长段同样受全部几何规则校验。普通直连的两端 5.5 规则保持原样。前往采用整数格八方向 A*，用到可达旧线区段的欧氏距离作下界；找到候选后仍检查可能更短的状态。达到 12 秒或 16 万搜索状态等上限且未完成比较时，提示“尚未确认最短线路”，不返回候选为成功，不静默改成直连。只显示新线和接入标记；已有通路以青色虚线叠加，便于确认实际经过的路线。

前往确认时不信任客户端携带的已有通路点，重新检查最新几何、旧线单/双向、所有途中 LN 与旧 Cross 状态；并发编辑造成通路失效则整次拒绝。保存新线后执行真实 K，再将唯一接入 Cross 设为普通连通（I / Connected），不自动使用 [ 单向换路；新线其他 Cross 全部不连通，线路本身继续遵守各自的单/双向属性。旧线本身及其他旧 Cross 设置保留。普通 K 重算按现有机制复用这个接入状态。失败回滚新线、Cross、投影与撤销历史，成功后一次 Ctrl+Z 撤销整次前往。网络结果未确认时保留同一编码重试；退出模式不能宣称线路必然未保存。

LN4、LN6、LN8、LN10、LN12 可选中后 Ctrl+C，Ctrl+V 进入鼠标落点预览；左键确认保存，Esc 取消。LN18 不复制。复制只携带边长、值、逻辑语言和说明，副本按新增规则生成编码，归当前登录用户，不复制旧位置、版本或权限。LN12 的值重复时按大写唯一规则加数字，逻辑语言保留；LN6 的逻辑语言按原文区分大小写唯一，重复加数字，值和原节点的 LN4 引用保留；LN8 只能 =、→、↔、¬、⊇、⊋、⊆ 或 ⊊，逻辑语言自动生成（¬ 对应 ¬(?)，其他符号同值），可重复，不加数字；旧单节点剪贴板中的 ¬ 逻辑会自动规范为 ¬(?)。旧 LN4 剪贴板仍可粘贴。所有编号、几何校验和位置重算由 Server 在同一事务内完成；预览不预占编号，成功提示实际采用的编号，失败保留落点预览供重试。编辑和 LN 菜单、工具栏提示及 F1 说明保持一致；文字输入框不拦截普通复制粘贴，单独 C 仍反转线路方向。后台 K/J 可继续运行，完成刷新不清除 LN 粘贴预览。

## 交互约定

- 流程图导入的每个 LN 必须填写非空白 logic（逻辑语言），最多 255 字符；事实、动作、判断、是/否和开始节点全部适用。导入窗口常驻提示，地图选点和校验预览先做本地格式检查，Server 在预览和提交时再次独立检查；错误带 LN 的 id，整批不写入。该要求仅约束流程图导入，不改变手动落点的新增流程。完整协议与 ChatGPT 任务模板同样要求审核稿逐个保留 value、logic 和分支条件，确认后转换 JSON 不得丢失逻辑内容；表达式作为文字保存，不自动执行或证明。
- 编辑菜单提供“导入 ChatGPT 给我的流程图…”：粘贴 ArgumentMap Flow v1 JSON，地图选点对应 origin LN 的半整数中心；可先预览，确认才提交。窗口自带设备排查示例；修改文本或位置后须重新校验。预览使用虚线，原地图不变；错误显示对象 id 和原因。导入期间保护其他编辑命令和重复提交，Esc 取消选点或窗口。服务端复用现有新增/校验/计算规则，在同一事务内读取最新全图并原子保存 LN、Road、Cross 和位置；预览后的多人冲突也重新验证。完整语言和接口见 ../FlowDiagramLanguage.md。
- 紧接导入菜单增加“流程图制作与导入说明…”，无需登录、可离线查看；导入窗口同样提供说明按钮和 F1。说明用原生只读文档显示，带可跳转目录、字段表、JSON 示例、制作步骤和常见错误；正文来自嵌入的 FlowDiagramLanguage.md，发布时无源码文件依赖。提供复制完整规范、含完整示例的 ChatGPT 任务模板、最小示例和分支示例；阅读/关闭说明不能改变当前地图、草稿或预览。
- “复制给 ChatGPT 的完整协议”面向没有本软件和聊天历史的接收者，复制自包含规范（含三份完整 JSON）及嵌入的资料/检索任务表。规定资料核验、事实/推断区分、必要澄清、对象映射、几何自查公式、最终只交付完整 JSON 及软件报错后的修正闭环。“复制分支示例”使用 LN 外双向连通的两路样例；另保留导入窗口原有的多层判断标签示例，并明确其 LN 内不连通 Cross 的语义。
- 流程图导入省略 Road.speed 时默认 100，显式速度仍按 5–500 校验并原样保存。三份制作示例均使用 100；窗口提示、制作说明和任务模板同步。制作时 Cross 优先 connected 或 disconnected，尽量避免单向换路；只有业务明确要求时使用两种单向状态。该偏好不改写显式状态，不改变 Road.direction 或 LN 内路口必须不连通的限制。
- K 保持计算 Cross；J 专门计算 LN 在线路上的位置，浏览和 LN 模式均可直接按 J。LN 的 IsChanged 位于 LogicalNodePositions 明细表，沿旧 FP 约定使用 -1（待算）和 1（有效），与 Cross 的 -1/0 区分。J 重新计算垂足与比例，恢复有效位置、删除未恢复的位置并插入新增关系；0 个位置仍保留 LN 本身和值、说明、逻辑语言。
- 线路修改、LN 移动、拆分合并及框选移动复用 J 的位置标记与重算逻辑，并在同一事务内完成；手动 J 后台逐个 LN 提交，可以修复待算、失效或缺失的位置关系。位置变化在 SQL 内先标 -1，再恢复 1 或删除；失败 rollback。整体移动只更新受影响的关系，保留其他线路的待算位置；K 不修改 LN 位置标记，J 不修改 Cross 标记。K/J 不占用整轮前台忙碌状态，其他用户也可新增、编辑、框选移动及导入；进度单独显示，刷新不得覆盖草稿和较新缓存。
- F7 / 编辑菜单 / 框选移动按钮进入整体移动：拖出矩形、松开后仅选全部节点和线段都在框内的完整线路，以及整个外接正方形都在框内的 LN4/6/8/10/12/18。仅中心在框内、只框入部分边角的 LN 不选；线路任一端点或中间折点在框外，整条不选；仅穿过矩形也不选。正好贴合选择框边界算完整框入，不作取整或容差扩选，LN8 倒角不放宽外接正方形规则。框内（含边界）Cross 仅当两条所属线路都完整选中时选中；缺少任一完整所属线路时跳过该 Cross，并显示跳过数量，不拒绝其他完整 LN、线路的移动和删除。被跳过的 Cross 不独立平移；提交时仍重算或清理选中线路的全部相关 Cross，同一交点身份仍成立时复用设置。单击、零宽或零高拖框在 WPF 本地提示按住左键拖出矩形再松开，不发送空选框请求；支持任意拖框方向。移动和 R 删除共用 Server 的同一包含判定，提交时按原框重读成员及版本。移动鼠标预览，左键或 Enter 落点；Esc 取消，F7 重新框选。整体偏移吸附整数，保持线路节点整数与 LN 中心半整数，不改变方向、折角或边长。
- 框选完成后 R 或“编辑 → 删除框选对象”删除原选中的完整线路与 LN，不按鼠标移动预览的位置重新取对象；未完成选择不会提交。Server 的 DeleteMapArea 接口验证 LoginCode，并在同一地图锁和数据库事务内重读框内成员、权限、锁定与版本，检测新增/移走/删除及 Cross 设置变化；不一致要求重新框选。关联 Cross、线路节点、LN 位置随对象一起清理；保留 LN 移除被删线路的位置并更新版本，保留无关待算标记。失败全部 rollback，界面保留选择可重试；成功同步三类缓存并退出框选，忙碌期间禁止重复删除、移动、取消与重新框选。
- 框选移动不拆开线路，不单独挪动 Cross。所选线路可有待计算的 Cross，无需等 K 完成，但必须属于当前用户且未锁定；LN 遵循原有编辑权限。落点时，在数据层同一个地图锁与 InnoDB 事务内读取最新全图，复核框选成员及版本，校验边界、重复点、重叠、不同线路正交、第三线不得经过 Cross、LN 接触/节点/斜穿/通行状态限制。合格后一起更新线路、LN、Cross 和所有 LN 位置；失败统一 rollback。Cross 以原两条线路编码加平移坐标恢复状态及单向换路方向，再重算序号、比例与版本。成功后无需额外 K/J；未选中的 LN 位置也随线路变化更新。
- 框选在私有快照上按当前线路推算 Cross，包含尚未入库的交点并排除已不在线上的旧交点，不消费 K 任务、不写数据库。提交时重新按同一方式推算；K 恢复交点或更新序号、比例等派生信息不会误报版本冲突。框选后其他用户修改框内对象或 Cross 状态时拒绝覆盖，要求重新框选；其他用户在目标处新增对象时使用提交时最新全图验证。忙碌时禁用其他修改流程，避免重复提交；失败保留预览可调整或取消。平移后不变的 SQL DECIMAL(20,18) 比例直接保留原始小数位，不通过 double 重建。
- 框选移动的 Cross 与普通 F6/K 复用标记、逐段恢复及清理机制：关联旧 Cross 标为待重算，保留旧记录和设置；平移后的对应记录也先标为待重算，只有重算确实找到才恢复为有效。最后只清理本次移动关联的剩余待重算 Cross，保留其他用户的待算任务。SQL 在同一事务内先将原记录 IsChanged 置 -1，重算结果写入时恢复 0（包括新坐标复用了另一个旧主键的情况），未恢复的旧记录删除。中途异常全部 rollback，外部只会看到提交后的完整结果，成功后无需再按 K。
- 菜单栏常驻；下方全部按钮统一收起或展开。右侧按钮、视图菜单和 Ctrl + F1 使用同一显示状态。
- 菜单按任务分组，用分隔线区分操作组；现有业务快捷键不重新分配。
- 菜单项右侧显示实际快捷键；按钮标出快捷键，悬停显示操作说明。
- Alt + F / E / C / V / H 打开菜单；方向键、Enter 和 Esc 使用原生菜单导航。
- 锁定和方向箭头菜单使用勾选状态；菜单、工具栏和地图状态同步。

## Cross 新限制的多人事务

禁止第三条线路经过 Cross 是逻辑地图新增的业务规则。F6 的几何校验、当前交点判断、线路替换和待重算标记必须处于同一数据层事务中。

MySqlLineRepository 先取得数据库的 Schema 命名锁，阻止业务事务与架构切换交错；在 READ COMMITTED 事务内先执行 MapMetadata Id=1 的 SELECT FOR UPDATE，随后才读取账号、线路、Cross 和重算标记。多个服务实例使用同一个数据库行锁；等待的操作在取得锁后重新读取并校验已提交的数据，不能同时依据旧快照通过校验。迁移期间额外使用原生表锁，防止不识别命名锁的旧客户端插入写入。

ServiceResult.Success 为 false 时明确 Rollback；SQL 或业务回调异常也 Rollback；全部检查和写入成功后才 Commit。登录会话校验通过 CurrentTransaction 复用同一事务。线路与 Cross 的版本冲突检查继续保留。

K 沿用原流程的事务边界：每次线段计算单独提交，全部线段完成后的清理另开事务。新增规则的计算前后校验都处于该次事务内，失败只回滚当前事务，已提交的其他用户操作保留。

ConcurrentMySqlChecks 使用两个独立服务实例、两个 MySqlLineRepository 和不同账号，验证同时保存交点线路时只有一个请求提交，失败请求不遗留节点、版本或标记；同时执行违规保存、K 和 Cross 设置时，失败请求的回滚不撤销其他用户已提交的 Cross 设置。TransactionChecks 用 MySQL 故障触发器验证写入中断后的回滚与重试。

LN8 使用青色 #0891B2 的倒角方形，宽高 8，四角各切去两条直角边为 0.5 地图单位的等腰直角三角形，不画圆弧。普通绘制、选中轮廓、放置/移动、框选移动及导入预览使用同一轮廓。值使用含 =、→、↔、¬、⊇、⊋、⊆、⊊ 的下拉框，逻辑语言随值同步且只读：¬ 对应 ¬(?)，其他符号（=、→、↔、⊇、⊋、⊆、⊊）与值一致，可以重复；全图数量不受限制。按绘图约定 = 关联两个 LN12 所指，→ 关联两个 LN6（前提到结论），↔ 关联两个 LN6（互相蕴含、逻辑等价），¬ 对输入 LN6 P 取反并以输出 LN6 Q 表达 Q ↔ ¬P，像 LN6 自由放置，不自动检查端点、不改变 Cross。几何约束仍以完整外接正方形校验。

K 使用独立后台计算状态，不占用前台保存状态。期间允许 LN、线路编辑及保存，未保存草稿不参与计算；重复 K 不创建第二轮。每段请求结束后让出 UI，前台忙碌时暂缓下一段；HttpLineClient 在同一客户端内串行发送业务请求，已排队的前台请求优先于下一段 K。后台计算消息独立于当前操作提示，完成或失败不弹模态窗口、不抢焦点、不重载 LN 和线路。完成后只刷新 Cross，读取期间若前台已更新交点缓存，丢弃旧的后台读取结果。关闭主窗口停止后续 K 请求，已开始的一段由 Server 正常提交或回滚，剩余待算标记保留。

### Ctrl+Z 数据库撤销

地图 Ctrl+Z 与编辑菜单调用会话认证的 UndoMap；每个账号最近 100 次实际地图变更存于数据库。整组操作整体恢复原编码及合法关联，冲突不覆盖其他用户。后台 K/J 不入栈，受影响关联按当前数据重算。文字框保留原生撤销，未保存草稿/预览和打开的编辑窗口必须先保存或取消；请求过程中 IsSaving 阻止重复按键。成功后一次替换三个地图缓存并清除旧选择，后台响应不得覆盖新缓存；失败保留选择与撤销记录。网络失败重试使用同一请求 ID，避免多撤销一次。

### LN 保护区域显示

LN 面板与 LN 菜单增加“显示保护区域”，默认关闭，地图快捷键为未占用的 G。开关、菜单和快捷键同步；输入框内 G 保留文字输入，修饰键和长按不触发重复切换。外围用无填充灰蓝虚线正方形表示，与 LN 同心，世界边长为 3×LN边长−1（LN4/6/8/10/12/18 分别为 11/17/23/29/35/53）。线宽不随缩放增粗，区域跟随缩放及新增、移动、粘贴、框选移动、导入预览。先绘制保护区域，再绘制 LN、线路、Cross 和文字。

### LN6 作用对象类型

仅 LN6 编辑/新增窗口显示 OperandKind：Class · 类、Instance · 实例、Custom · 自定义。默认 Custom，打开旧节点保持原文；切换类型和输入即时按固定 en-US 规则规范逻辑语言，Class 大写、Instance 小写、Custom 原文，显示值与说明不转写。服务端再次规范后判重，冲突保留草稿和原引用。未保存的类型修改也阻止移动。只有大小写处理，不解析表达式或自动查找目标节点。复制/粘贴、导入和数据库撤销完整保留字段。

LN10 属性格式（架构 32）：编辑只自动转小写括号前的类名，不对 name、id 等属性内容转换大小写；完整值上限 220 字符，隶属表达式仍最多 255 字符。父类改名及同组复制/导入编号只替换实例前缀，保留括号属性；删除父类的限制不变。旧实例升级为 类名小写(id=原节点编码)，原编码、位置、说明保留；快捷落点使用新节点编码作为临时 id。格式不合法或父类不匹配时不保存，实例值和逻辑语言仍可重复。

LN10 多属性（架构 33 引入，连接符现采用架构 35 的 ∧）：允许 human()；括号内可用逗号分隔 id=1,name=要瑞卿。只读逻辑按属性顺序展开，如 human(id=1,name=要瑞卿)∈HUMAN∧1∈HUMAN.ID∧要瑞卿∈HUMAN.NAME，不插入空格。属性名仅在引用部分转大写，原实例值保留属性大小写与顺序；logic 单独放宽至 4096 字符，其他 LN 仍 255。编辑、定位、粘贴、整组导入、父类改名、数据库迁移和撤销保持同一规则。

LN10 可选别名（架构 34 引入，连接符现采用架构 35 的 ∧）：完整实例值括号后可用空白分隔名字，如 human(id=1) 甲a1；逻辑第一项使用名字，得到 甲a1∈HUMAN∧1∈HUMAN.ID。别名保留大小写及中文，可重复，不参与父类匹配。删掉别名恢复完整实例值作主体；父类定位、改名、整组编号、剪贴板、导入及撤销均保留属性与别名。别名功能不改写无别名实例的值；其逻辑连接符按架构 35 统一升级。
